Kontext verstehen und erweitern I

Das Context Window einer KI

  • Context Window ist Wissen der KI
  • alles außerhalb ist nicht bekannt
  • besteht aus Tokens (1 Token ca. 0,75 Wörter)
  • jede Session hat eigenes Context Window

[System-Prompt] + [Chatverlauf] + [Tool-Aufruf] + [Deine Frage]
       ↑                ↑               ↑                ↑     
       └──────────────────── Context Window ─────────────┘

Tool und Context Window


User:      "Wie wird das Wetter morgen in Hamburg?"

Modell:    → ruft Tool auf:
           { tool: "weather_fetch",
             input: { city: "Hamburg", date: "morgen" } }

Tool:      → gibt zurück:
           { temp: "18°C", rain: "30%", wind: "15 km/h" }

Modell:    → liest Ergebnis & antwortet:
           "Morgen in Hamburg: 18°C, leichter Regen möglich."

Praxis Tipps für Context Window

  • Achtung, vor großem Context Window
  • Vorsicht bei Tools und Dateien
  • Session ggf. komprimieren mit /compact
  • versch. KI-Modelle unterstützen versch. Window Größen (GPT-3.5 16k Tokens, Gemini 1.5 Pro 1.5 Mio Tokens)

Agenten und Subagenten in OpenCode

Primary Agents und Subagenten

🤖 Primary Agent 🕵️ Subagent
Beispiele Build, Plan explore, general
Aufruf Du, Wechsel mit Tab Du mit @ oder der Agent selbst
Aufgabe Hauptgespräch in deiner Session Teilaufgabe in eigener Unter-Session

Subagenten kennenlernen

  • explore Subagent erkundet
  • general Subagent für allgemeine Aufgaben
  • Aufruf mit @ oder durch den Agenten selbst
  • Ergebnis kommt zurück in die Haupt-Session

Warum Subagenten?

  • Arbeit läuft in eigener Child-Session
  • Haupt-Session bleibt übersichtlich
  • Erkunden und Umsetzen trennen

🏋️ Übung: Agenten ausprobieren

  1. Frage zum Winkelshop direkt in der Session stellen (z.B. "Wie wird der Warenkorb berechnet?")
  2. Dieselbe Frage mit @explore stellen, Session-Größe vergleichen
  3. Mit @general kleine Aufgabe delegieren (z.B. Unit Tests)

Agent für Review einer Feature Umsetzung erstellen

Erstelle einen Subagent cross-review der den Code prüft auf versch. Kriterien wie Architektur, Sicherheit oder weiteres. Die Ergebnisse sollen strukturiert ausgegeben werden. Der Agent darf nichts verändert (setze Rechte).

Sicher Opencode einsetzen

Sicher Opencode einsetzen

  • Agent hat Zugriff auf dein Dateisystem, Terminal
  • Agent kann Code ausführen, Dateien löschen, Commits machen
  • Agent nutzt Credentials und Umgebungsvariablen
